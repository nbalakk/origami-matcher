# Конструктор заливочных файлов

[![CI](https://github.com/nbalakk/origami-matcher/actions/workflows/ci.yml/badge.svg)](https://github.com/nbalakk/origami-matcher/actions/workflows/ci.yml)

Инструмент для подготовки заливочных CSV: подставляет новые ставки и недельные бюджеты
из мастер-файла в выгрузку, собирает файл из нескольких пулов кампаний, проверяет его
**до** заливки и сверяет результат **после**.

Работает целиком в браузере: файлы не загружаются ни на какой сервер, интернет не нужен.

**→ [Открыть инструмент](https://nbalakk.github.io/origami-matcher/)** · доступ по паролю команды

---

## Что он делает

| Возможность | Зачем |
|---|---|
| Матч по `CampaignID` (+ `GoalID` для ставок) | подставляет значения ровно в те строки, куда можно |
| Правила | несколько пулов кампаний одним файлом, каждый со своим листом и охватом |
| Два сценария | дополнить исходник целиком либо собрать новый файл только из нужных РК |
| Выбор листов | из книги на 25+ листов читаются только отмеченные, с прогрессом |
| Пред-полётная проверка | независимый аудит результата: файл либо безопасен, либо нет |
| Сверка заливки | свежая выгрузка + залитый файл → что реально применилось |

Формат сохраняется байт в байт: BOM, `CRLF`, разделитель `;`, кавычки, `="123"`.
Все колонки кроме значения не трогаются.

## Архитектура

```
src/
├── core/            чистая логика, без DOM — тестируется в Node
│   ├── fmt.js       разбор и формирование CSV, числа, округление
│   ├── export.js    разбор заливочного: цели, аккаунты, размещения, стратегии
│   ├── sheet.js     разметка листа: строка заголовков, столбец ID, подбор столбцов
│   ├── rules.js     правила → карта значений, конфликты
│   ├── build.js     сборка файла: сценарии, охват, диагностика
│   ├── audit.js     независимая проверка готового файла
│   └── verify.js    сверка «что реально встало»
├── xlsx/reader.js   чтение xlsx (zip + xml) без внешних библиотек
└── ui/              интерфейс: разметка, приложение, вход
tests/
├── suite.js         общий набор проверок (Node + браузер)
├── core.test.js     раннер для node --test
└── index.html       раннер в браузере (включая xlsx)
tools/build.py       сборка index.html и dist/
```

Слои разделены жёстко: `core/` не знает про DOM и браузерные API, поэтому его можно
гонять в CI обычным `node --test`. `ui/` только рисует и ничего не вычисляет.
Чтение xlsx вынесено отдельно — единственное место, зависящее от браузерных API
(`DecompressionStream`, `DOMParser`).

## Разработка

```bash
npm test                  # проверки ядра (node --test), без зависимостей
python tools/build.py     # пересобрать index.html и dist/
```

Тесты в браузере (полный набор, включая xlsx): открыть `tests/index.html`,
либо кнопку «самопроверка» в подвале самого инструмента.

Сборка склеивает модули в фиксированном порядке и выдаёт два артефакта:

* `index.html` — точка входа для GitHub Pages, подключает `src/**` с версией по хешу
  (чтобы у пользователей не залипал кеш);
* `dist/origami-matcher.html` — автономный файл: всё внутри, работает офлайн двойным кликом.

CI на каждый push прогоняет тесты, пересобирает и проверяет, что собранные файлы
в репозитории не разошлись с исходниками.

## Границы

**Строки для кампаний, которых нет в выгрузке, для ставок не создаются никогда.**
Какие цели подключены к кампании, из мастер-файла не выводится, а сервис отбивает
весь файл, если цель не совпала с фактической автостратегией. Такие кампании
инструмент показывает отдельным списком — их добирают перевыгрузкой.

Для бюджетов строку собрать можно (там нет целей), но только с известным `AccountID`:
он берётся из выгрузки по логину либо вводится вручную. Номер аккаунта не выдумывается.

**Про пароль.** Это барьер от случайных посетителей, а не защита данных: исходники
открыты, и экран входа обходится. Скрывать нечего — инструмент ничего не хранит
и никуда не отправляет, все файлы обрабатываются в браузере.
